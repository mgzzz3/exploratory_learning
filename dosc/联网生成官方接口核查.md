## 新发现的兼容问题：官方工具丢失 HTTP 状态属性

对官方 Search 和 Extract 分别注入 401、403、429、503 响应，共八种情况：

- 官方工具返回 `{"error": Exception(...)}`。
- 异常没有 `status`、`status_code` 或 `response` 属性。
- 数字状态码仅留在官方构造的固定文本格式 `Error <status>: <reason>` 中。
- 同步接口也把状态信息转为普通异常文本；改用同步请求不能解决该限制，且不符合异步取消设计。

证据由 `backend/tests/test_tavily_official_contract.py` 固化。该文件的状态丢失测试是**上游行为表征**，并非接受应用继续用宽泛字符串猜测错误类别；如果后续升级恢复了类型化状态，这些测试会提示重新评估兼容策略。

任务 5.10 要求“不以异常文案匹配类别”，同时要求保留认证、限流等不同失败原因。2026-08-31 用户已明确同意最小兼容例外：在唯一官方适配边界严格解析固定格式中的数字 HTTP 状态码，立即转成安全的类型化领域错误；不读取自由文案判断类别，不输出原异常，未知格式失败关闭。该边界已同步至变更的 design/spec/tasks，并按 TDD 实现；后续实施证据见《联网生成 TDD 实施记录》。

这一发现不是“高情商聊天卡住”的唯一根因结论；既有证据丢失和预算不收敛问题仍待后续任务修复。

## 2026-08-31 前端与安全诊断实施复核

- [Taro.request / RequestTask](https://docs.taro.zone/docs/apis/network/request/)：调用返回的请求任务保留 `abort()`，页面取消调用实际任务，而非仅忽略 Promise；统一将两种创建请求设为 90000 毫秒。H5 调用已观察服务端断连取消；微信实际操作仍待验收。
- [Taro Hooks](https://docs.taro.zone/docs/hooks/)：使用 `useDidHide`、`useUnload` 清除页面内许可并取消请求；额外保留 React 卸载清理，避免换页/退出后迟到响应复活入口。
- [React useSyncExternalStore](https://react.dev/reference/react/useSyncExternalStore)：`getSnapshot` 返回缓存对象，仅状态更新时替换；订阅函数保持稳定，许可 token 不放进暴露给 React 的快照。
- [LangSmith 条件追踪](https://docs.langchain.com/langsmith/trace-conditionally)：研究图调用处使用 `tracing_context(enabled=False)`，不依赖部署环境是否误开全局 tracing；真实 LangChain middleware 测试验证该边界。
- [Python logging LogRecordFactory](https://docs.python.org/3.11/library/logging.html#logging.setLogRecordFactory)：在记录创建时清理消息参数、异常链及 stack，专用 formatter 只序列化白名单事件。按本机 Uvicorn formatter 实际契约保留五个安全占位参数，避免脱敏引起日志格式异常；Alembic fileConfig 后重新启用专用诊断 logger。
- 重新核对 [LangChain 结构化输出错误处理](https://docs.langchain.com/oss/python/langchain/structured-output)：错误反馈函数只抽取 Pydantic 的允许字段路径和错误类型，绝不把原输入/供应商错误文本拼入纠错反馈；与已有一次纠错预算共用。

这些是官方接口与本机契约核查，不意味着模型自然语言输出质量或双端 UI 已完成验收。对应红灯/绿灯、真实调用失败与遗留门禁已如实记录。
