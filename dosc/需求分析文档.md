# 《AI万物学堂》MVP 最小可行性产品需求文档 (PRD)

## 1. 产品定位与核心价值
- **定位**：一款基于微信小程序的 AI 互动游戏化学习工具。
- **核心价值**：用户输入任意想学的知识，AI 自动将其转化为“聊天闯关游戏”，通过趣味问答和“大白话”解释，让碎片化学习变得轻松、上瘾。

## 2. MVP 核心用户旅程 (User Flow)
进入首页 -> 输入想学的主题 -> 自动进入游戏舱 -> AI出题/用户答题 -> 答错扣血（看广告/分享复活）-> 通关结算。

## 3. 功能需求定义 (Functional Requirements)

### 3.1 首页模块（万物生成器）
- **核心功能**：
  - **自定义输入框**：一个简单的文本输入框，提示语：“今天想轻松学点什么？”。
  - **一键生成按钮**：点击后，前端展示加载动画（提示语：“AI 正在为您筑界，请稍候...”），同时向后端发送请求。
  - **极简推荐标签**：放置 4 个死数据标签（如：Python基础、高情商聊天、咖啡拉花、理财小白），点击直接自动填充输入框，降低用户冷启动思考成本。

### 3.2 游戏舱模块（极简对话流核心）
- **界面表现**：采用类似微信聊天的对话流布局。
- **游戏规则**：固定每种知识只有 **3 个关卡**（关卡一：新手，关卡二：进阶，关卡三：Boss战）。每关只有 1 道题。
- **AI 交互逻辑**：
  1. **引入**：进入关卡，AI 发送 1-2 句极其通俗的知识点介绍。
  2. **出题**：AI 紧接着发送一道**三选一的单选题**。界面下方弹出 A、B、C 三个选项按钮。
  3. **判定**：
     - **用户选对**：播放正确音效/动效，AI 夸奖一句，进度条推进，自动进入下一关。
     - **用户选错**：**触发“大白话名师”弹窗**。AI 用一个生活中的精妙比喻解释错因。同时**扣除 1 点血量（体力）**。

### 3.3 商业化与裂变模块（血量与充能）
- **血量机制**：用户初始拥有 3 点血量（以 3 颗爱心 ❤️ 表示）。
- **熔断机制**：血量归零时，游戏暂停，弹出【充能弹窗】。
- **充能渠道**（二选一）：
  - **看广告**：点击“看视频复活”，调用微信激励视频广告组件。完整播放完广告后，血量回满，继续游戏。
  - **群裂变**：点击“呼叫朋友帮忙”，触发微信分享给好友/微信群。分享成功后，血量回满。

### 3.4 基础底层模块（合规与登录）
- **静默登录**：用户无需注册，进入小程序自动调用 `wx.login`，绑定微信 OpenID，确保能记录其剩余血量。
- **内容安全安全阀**：用户输入的“想学主题”，在提交给 AI 之前，必须先调用微信官方的 `msgSecCheck` 进行文本反垃圾过滤。若违规，直接弹窗提示“该主题不可描述，请换个健康的词试试”。

## 4. 技术实现难点与独立开发应对方案
- **难点：AI 生成格式不稳定，导致前端解析崩溃。**
  - *应对方案*：后端调用大模型时，必须在 System Prompt 中强制要求 AI **严格输出 JSON 格式**（包含知识点、题目、3个选项、正确答案、错题大白话解释）。后端解析出 JSON 字段后，再结构化地呈现在小程序前端，严禁让 AI 直接输出纯文本。

## 5. 商业收益预估 (ROI)
- **成本**：DeepSeek/OpenAI 接口费（极低，100万 Token 仅需几元人民币）+ 腾讯云低代码/轻量服务器费用（几十元/月）。
- **收益**：微信激励视频广告曝光收益（eCPM 通常在 30-100 元不等，即每 1000 次广告播放可带来 30-100 元收入）。
- **结论**：只要单个用户由于“卡关”看完 1-2 个广告，其产生的收益就足以覆盖他本次游戏消耗的所有 Token 成本。项目天然具备正向现金流。
