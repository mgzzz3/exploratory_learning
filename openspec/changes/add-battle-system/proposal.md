## Why

现有学习流程是纯单人闯关，缺少社交驱动的学习动机。增加好友约战后，房主用一个关键词发起挑战、双方作答同一套题并分出胜负，用轻量的竞争关系提升学习趣味和分享传播。

## What Changes

- 新增好友对战玩法：房主选择一个关键词发起对战，通过微信分享卡片邀请好友加入，两人作答由同一关键词生成的同一套三关题目。
- 对战为异步各自作答：双方从同一信号（双方就绪）开始，各自独立答题，过程不要求实时同步进度；先答完的一方在结果页等待对方完成或超时。
- 对战答题规则与单人闯关不同：不使用脑力（心）、不重试、不支持广告复活和好友助攻；答错直接进入下一题，全部题目作答完毕后在结果页逐题展示自己的选择、正确答案与解释。
- 胜负判定规则：先比答对题数，多者胜；同分比总用时（从双方就绪信号到本人最后一题提交），短者胜；完全相同判平局。
- 房间生命周期含两个 3 分钟窗口：题目就绪后 3 分钟内无人加入则房间作废；对战开始后 3 分钟内未完成则按当前进度结算（答对数优先，已完成者优于未完成者，双方均无作答记录则房间作废）。
- 答题公平性约束：对战期间题目下发 MUST NOT 包含正确答案，判定全部在服务端完成；结算前客户端 MUST NOT 能获取本房间任何正确答案。
- 复用现有题目生成策略（grounded / legacy / basic）与三关题目结构，对战房间只生成一套题，双方作答同一套题。
- 房间创建与出题解耦：房主发起后即可分享邀请卡片，题目在后台生成；挑战者加入时若题目未就绪，显示准备中状态。

### Non-goals

- 不做随机匹配、匹配队列、段位或排行榜。
- 不做答题过程中的实时进度同步（WebSocket / 轮询对手进度）。
- 不做多于两人的对战、观战或回放。
- 不改动现有单人闯关、复活、助攻与分享行为。

## Capabilities

### New Capabilities
- `battle-system`: 好友对战全生命周期——房主建房与分享邀请、挑战者加入、双方就绪与统一起点、各自作答与计分、超时结算、结果页逐题复盘与胜负展示，以及答案不下发的公平性约束。

### Modified Capabilities

无。`grounded-game-generation` 等既有能力的需求不变，对战仅复用其生成结果。

## Impact

- 后端新增对战路由（建房、加入、就绪、查询房间状态、提交答案、结算与结果）、对战服务层与结算逻辑；新增对战房间与参与者数据表及迁移；复用现有 `QuestionGenerationStrategy` 与 `LearningSession` / `Level` 生成与存储。
- 前端新增对战页面流程（建房等待、受邀加入、就绪倒计时、对战答题、结果复盘），分享卡片携带房间入口；对战答题页不渲染脑力、复活与助攻入口。
- 微信分享卡片路径新增对战房间入口参数，现有游戏分享路径保持不变。
- 不新增后端依赖与外部服务；对战不引入 WebSocket，等待对方完成时使用轻量轮询查询房间状态。
